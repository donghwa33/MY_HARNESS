# 00. 전체 흐름

| 단계 | 시간 비중 (예시) | 핵심 | 문서 |
|---|---|---|---|
| S0 셋업 | ~5% | 하네스 설치 → codex → 요구사항 확인 → 데이터 인벤토리 위임 | 01 |
| S1 인터뷰·합의 | ~10% | 요청자 인터뷰 ∥ Codex 인벤토리 → AGREEMENT 확인 | 02 |
| S2 정제 | ~20% | 프로파일 → 결정(확실성·추천) → 정제 코드·테스트 | 03 |
| ↳ HANDOFF #1 | | 새 메인 세션 | 07 |
| S3 분석 (+UI) | ~30% | 시계열 → 측정 → 층화 → 교란 → 독립 근거 → 분해 (→ UI) | 04 |
| ↳ HANDOFF #2 | | 새 메인 세션 + 레드팀 세션 | 07 |
| S4 검증 | ~10% | 레드팀 · 독립 재계산 · 민감도 · UI 확인 | 05 |
| S5 산출 | ~15% | 지정 파일 매핑 · 보고서 · 조치안 · 재현 · 회신 | 06 |
| 마감 | ~10% | explain pack · HANDOFF #3 · 최종 커밋 | 08 |

## 시간 규칙
- 마감 시각이 있는 작업이면 마지막 10% 는 정리·설명 준비·인계에 남긴다. 그 이후 새 분석을 시작하지 않는다.
- 남은 작업은 HANDOFF 의 열린 질문으로 남긴다.

## 병렬 원칙
- Codex 가 오래 걸리는 작업(코드 작성·실행)을 하는 동안 사람은 인터뷰, 문서 검토, EXPLAIN 정리를 한다.
- 터미널을 용도별로 나눈다: T1 메인 codex / T2 레드팀 codex / T3 서버 / T4 수동 명령.
- Codex 가 승인 대기 상태면 진행되지 않는다. 다른 일을 하다가도 주기적으로 확인한다.
